# Luma：从咖啡店到家中早餐

日期：2026-09-23。用途：本轮产品与交互实现规格、验收依据。

**状态约定：**“现有基础”指本轮开工时已经在代码中存在；“本轮要求”是这次要实现并验证的行为，不代表单凭本文就已经完成。最终实现、测试和实机边界以本轮 `VERIFICATION.md` 为准。

## 1. 版本边界与产品目标

旧版代码保留为 `backup/pre-world-loop-20260923`，基准提交 `c880bd2`。另有离线 Git 备份：`/Users/wufengqing/Documents/ChatGPT/英语学习/backups/2026-09-23/luma-before-world-loop.bundle`。这保存的是代码版本，不是用户浏览器的学习记录或服务密钥。

本轮把原本分散的短任务连接成一段可继续的生活：在街角咖啡店说清订单，之后回到家中早餐，再用一次“告诉别人自己想喝什么”的能力。每次仍是短任务，不要求用户先学知识再进场景。

产品要回答三个问题：

1. **我现在要做什么？** 一件具体的小事，例如替朋友带一杯咖啡。
2. **为什么推荐我接下来做这件事？** 理由来自刚才真实使用的帮助和完成情况。
3. **我比之前哪里更能自己应付？** 展示表达、帮助条件和发生场景，不把任务通过换算成“英语掌握率”。

目标用户是有少量英语基础、认识一些词却难以开口的中文母语成人。中文求助一直可用。人物可以简短问候，用户也可以直接进入正事。

## 2. 范围与已有基础

| 范围 | 现有基础 | 本轮要求 |
| --- | --- | --- |
| 咖啡店 | C01 自己点单、C02 替朋友带咖啡、C03 处理错单、C04 独立挑战；订单会更新场景 | 保留任务和已完成记录；把完成后的下一步改成有理由的推荐 |
| 家中早餐 | 选牛奶/水、回应杯子请求、说明是否还要；已有家中人物与场景 | 作为咖啡店后的关联经历；明确是家中早餐，不命名为尚未制作的早餐店 |
| 学习证据 | 成功、未确认、技术异常、字幕/中文/示范等帮助、听与说的条件、到期复练 | 用已有事实组织推荐和前后对比，不虚构能力分数 |
| 入口 | 首页继续任务、咖啡店选择任务、世界入口、笔记 | 继续仍是一键主操作；推荐、重练、换任务互不强迫 |
| 难度 | 有字幕引导、无字幕聆听、主动帮助 | 同一任务可自愿少看帮助再试；随时恢复，避免一下改变所有条件 |

本轮不扩建纽约城市，不增加缺货、付款失败等尚未实现的剧情，不把机场/办公室原型删除或包装成已完整连接的主线。它们继续作为现有独立场景入口。暂不做发音评分、语法能力总分、词汇量推算或通用 AI 课程生成。

## 3. 学习内容与事件映射

代码中的 `taskId` 是任务内的交流节点；界面中的“小任务”是一次完整经历。普通续练只保存到小任务，不从上一句对话继续。

| 事件 | 交流内容 | 主要能力 | 帮助与判断边界 |
| --- | --- | --- | --- |
| C01 给自己点一杯 | `coffee-order` → `coffee-size` → `coffee-service` → `coffee-thanks` | 饮品选择、杯型、堂食/带走、礼貌回应 | 接受单词、短句和等义表达；不把仅说 yes 当作尚未确定的饮品 |
| C02 替朋友带一杯 | 同一组节点，按便条说清小杯拿铁带走 | 用既定条件完成交流 | 用户可以一次说完整，也可以逐项回答；不重复索取已经确认的信息 |
| C03 这杯拿错了 | 对实际收到的杯型提出修正 | 发现不一致、表达改正 | “Small” 可以推进；必须同时更新人物回应、订单和画面 |
| C04 自己应付新订单 | 同一组节点，默认少给帮助 | 在当前帮助条件下独立交流 | 使用帮助不会锁关；有字幕或示范后不能写成无帮助完成 |
| 家中早餐 | `breakfast-drink` → `breakfast-cup` → `breakfast-more` | 饮品选择、回应物品请求、调整份量 | 使用已有牛奶/水、杯子和份量画面；不声称点了咖啡 |

咖啡店的 `coffee-order` 与早餐的 `breakfast-drink` 共享 `choose-drink` 能力：理解选择并说出想喝的东西。将 Latte 换成 Milk 是一次有限的变式；在两个场景都留下符合条件的独立英语语音回应，才可以写“曾在咖啡店和家中早餐独立说出饮品选择”。不能据此写“饮品表达已掌握”或“所有餐厅都能应付”。

其余节点各自保留能力标识。早餐“递杯子”与咖啡店“选杯型”不是同一能力，不因都有 cup 就合并。

## 4. 下一段经历如何决定

每次只突出一个推荐，推荐附一条用户能理解的理由，其他选项放在次级位置。用户主动选择的任务永远优先于推荐。

### 首页优先级

1. **有未完成的小任务：**主按钮“继续任务”。从该小任务开始，不恢复半句话、旧订单确认或上次任务内节点。旁边保留“选择任务”。
2. **没有未完成任务，且有到期复练：**推荐“隔一段时间，再试一次”，说明上次练了什么；用户可以换任务。已完成咖啡任务序列不得覆盖到期复练。
3. **没有待继续或到期项：**采用上次结算形成的推荐；新用户先进入 C01。

### 结算推荐

推荐以刚完成的会话为边界，不能把早前另一场景的帮助套到这次任务。

| 当前证据 | 推荐方向 | 可用文案 | 可选替代 |
| --- | --- | --- | --- |
| 有确认完成，但需要中文、关键词或完整示范 | 熟悉事件中再试，或先看一个有用表达 | “刚才借助示范说出了饮品，这次试着自己说。” | 直接进入下一件事；微练习可跳过 |
| 能自己说出英语，但听题借助了字幕或重听 | 自愿试一次少看字幕 | “刚才能自己回答，这次先听听对方怎么问。” | 保留字幕继续；随时开帮助 |
| 咖啡店饮品选择已留下独立表达 | 去家中早餐使用同一能力 | “刚才会说想喝什么了，回到家里换一种饮料试试。” | 下一咖啡任务、再练本次任务 |
| 早餐已完成 | 建议隔天回到上次咖啡小任务，允许现在开始 | “早餐告一段落。建议明天回咖啡店再试试；现在想练，也可以直接开始。” | 复练早餐、选择其他咖啡任务 |
| 缺少可判断证据、旧记录帮助条件不明 | 按熟悉的方式再试，不擅自提高难度 | “这次的记录还不足以判断独立表达，暂不提高难度。” | 直接去准备早餐 |
| 只有技术异常，未确认有效回应 | 恢复或重试当前任务 | “刚才连接中断了，可以重新开始这件事。” | 返回首页；不降级、不记弱项 |

推荐不是课程门槛。使用过帮助不应永远锁在原任务；主动反复练习不增加“掌握等级”。本轮规则选择预制事件，不允许模型临时改写订单事实或制造不存在的剧情。

## 5. 页面与交互流程

### 5.1 首页：继续这段生活

沿用现有场景图、旅程节点和底部任务区。主按钮保持直接开始/继续；“选择任务”是独立轻入口。推荐原因最多一小段，放在任务内容区域，不遮人物和单词。

有旧进度时明确“从本任务开头继续”；完成任务的勾选保留。选择已完成 C01 不会撤销 C02/C03 的完成记录，也不会篡改未尝试的学习证据。

点主按钮后只启动一次任务。场景准备未完成时重复点击不创建第二个会话。返回首页时释放当前语音，首页自身不收音。

### 5.2 任务选择与场景介绍

进入选择页仅查看与选择，不创建练习证据、不打开麦克风。任务详情以短说明展示要办的事情，按钮始终可见；内容溢出时滚动正文，不把整张图片和按钮撑出屏幕。

关闭、返回、点击遮罩：回原页面，不改变当前选择或未完成任务。点击具体开始按钮才确认选中的事件；首次收音说明仍由用户确认后开启。

### 5.3 场景交流

中央人物、物品和词语是主内容。顶部只留必要任务信息与订单状态；不新增推荐卡、课程进度或微练习覆盖层。对话区延续紧凑布局，人物名在气泡外，识别确认用独立轻状态，避免重复占两行。

人物可以用一句问候开场，随后提清楚问题。用户答 Hi 可以自然接一句再回问题；用户直接说 Latte 立即处理饮品，不要求先回答寒暄。

回答已被收到、正在判断、人物正在回应是三个不同状态。识别中的片段不反复当成最终回答；同一用户回合只落一次有效证据和一次推进。模糊回答先澄清，不自动选择未表达的商品。中文求助先解释，再让用户继续原目标。

帮助通过一个熟悉的入口提供重听、意思、关键词/半句和示范。不是七层闯关菜单。看过帮助后关闭面板，当前任务继续；关闭面板不清除“本次用过帮助”的事实。

静音、返回、取消任务都会停止收音或撤销当前回调。晚到的识别/语音结果不得改动新的任务、订单、会话或帮助记录。

### 5.4 完成页：发生了什么、下一步做什么

页面从上到下为：实际结果 → 本次完成条件 → 一个推荐事件和原因 → 次级入口。

实际结果例如“这杯咖啡点好了”“早餐准备好了”。条件可以是“用英语说清了饮品”“听题时看过字幕”“这次借助了完整示范”；不同时出现互相矛盾的“独立完成”和“用了答案”。

主按钮开始推荐事件；次级操作保留“再练一次”“选择任务”或“回到旅程”，不一次堆满多张行动卡。用户不点击时不自动切换场景、申请收音或推进任务。

点下一步后一次性提交旧任务完成状态，再创建新会话。快速双击和页面重复渲染不能重复增加完成次数。返回首页后的主推荐应与刚才结算一致，除非用户选了另一个任务或已有更高优先级的未完成任务。

### 5.5 可跳过的表达小练习

仅在这次确实使用过相应帮助、且有准确可教内容时，出现“带走一句有用的表达”。每次最多一个表达。例如饮品选择的 `A latte, please.` / `Milk, please.`，提示“换成你想喝的东西”。

当前实现将它折叠在“顺手学一点 · 可跳过”中。点开先看短解释和关键词，主动点“看一个完整例子”才揭示整句，不制作未经证据支持的语法诊断。“回到场景试着说”进入这次表达对应的原场景；底部推荐按钮和替代入口始终保留。用户可以直接走下一段，或收起这块，不影响任务完成和下一步资格。

看过关键词或例子只能算接触过表达，不能算说会了。若同一天下一场景出现同一能力，应把这次学习作为该能力的帮助条件带入，不能切换场景就洗掉提示；仅进入后立即返回、没有有效回应，不能消耗掉这条帮助记录。只有真正开启新一轮练习才记录新会话；打开微练习、关闭、重复查看不制造空会话。这是保守的本轮产品规则，不等于证明跨天提示一定失效。

本轮不额外建立一套语音评分练习：通过后续情境中的真实表达检验是否能用。若后续增加单独开口练习，必须明确显示其状态和完成条件，不能用点按钮代替英语语音证据。

### 5.6 笔记与隔天再遇到

笔记首屏是具体场景中的一次复习：场景图、要做的小事和直接开始按钮。只有出现真实改善时，才展示一条简短的前后对比；详细条件及历史汇总收进可展开的练习足迹。没有进步时隐藏进步区。

可显示：

> 上次 · 咖啡店：看过完整示范后说出饮品。  
> 这次 · 家中早餐：自己用英语说出了选择。  
> 换了一个场景，再做到了一次。

若本次仍用了帮助，就如实显示；若条件未知，显示“当时的帮助条件未记录”。只有一次记录时将事实保留在历史中，不捏造“以前不会”。

到期提醒只意味着按产品默认间隔适合复练，不代表遗忘。已有 1/3/7 天规则属于可调整的产品安排。没有到期记录时显示下一次安排或中性空态，不每天伪造新剧情和连续天数。

用户主动点“今日复练”时应进入对应能力的复练，不能被另一个保存中的普通任务带走。针对某一能力的短复练可以从对应节点开始，但这是用户明确选择的独立复练入口，不是恢复普通任务的中间进度。判断延迟保持必须核对间隔、上次证据及期间是否再次看过同能力示范；不合条件只记录本次回应。

## 6. 状态、保存与迁移

| 状态 | 页面行为 | 保存与证据 |
| --- | --- | --- |
| 全新用户 | C01 入场，说明一个词也可以，帮助随时可用 | 不预填能力或天数 |
| 任务中退出 | 首页提供继续与选择任务 | 保存场景、小任务、变体和模式；普通继续从该任务首步开始 |
| 单次任务完成 | 结果页出现下一事件 | 完成幂等；新的练习是新会话，旧帮助不误关联新回合 |
| 老版节点存档 | 保留当前小任务与已完成任务 | 将普通续练节点归零，清理旧局部订单/对话恢复状态；历史证据保留 |
| 旧版学习证据条件不明 | 中性展示，可再练 | 不追认无字幕、无提示、迁移或保持能力 |
| 所有咖啡任务已完成 | 可去早餐、等待复练、重访任务 | 不把全任务完成写成“咖啡店已掌握” |
| 没有有效语音证据 | 显示已体验/尚待记录 | 点选、文本、中文成功分别记录，不能冒充英语口语 |
| 本地存储不可用 | 仍可练，轻提示本设备暂不能保存 | 不崩溃、不编造上次进度 |
| 权限拒绝/离线/连接超时 | 明确重试或返回，保留恢复入口 | 技术错误不扣分、不记弱项、不自动升降难度 |

跨场景练习时仅传递已知、有关联的帮助条件；不要传递未确认的答案或整个旧场景状态。会话标识、用户回合标识和目标能力三者一致才可写入证据。重复的完成、重连重放与延迟回调必须幂等处理。

## 7. 验收清单

### 功能与学习逻辑

- 新用户从咖啡 C01 开始；先问候或直接点饮品都能推进，不重复问已经确定的内容。
- 已做到 C03 的用户仍可选择 C01；主按钮继续当前任务，不强迫先经过任务选择器。
- 咖啡和早餐普通任务退出再进从本任务首步开始；已完成的小任务记录不丢失。
- 咖啡饮品独立表达后能进入真实家中早餐；早餐的人物、词语和饮品准确，不显示机场或不存在的早餐店。
- 使用帮助、听题借助字幕、独立表达、条件未知得到相应推荐理由；不因技术异常降级。
- 用户可以拒绝推荐、跳过微练习、回到世界或选择任务，不被重练循环锁住。
- 查看微练习示范后立刻到早餐回答，不被错误计为完全无帮助；没有查看示范则不凭空添加帮助。
- 已到期复练不会被咖啡固定顺序盖掉；主动复练入口不会被无关未完成任务劫持。
- 比较卡只有在有对应历史证据时出现；区分听懂与说出，条件不明不推定独立，无虚构百分比。
- 重复点击、重复结算、退出后旧回调、快速换任务不会重复建会话、双重推进或污染帮助证据。
- 老记录可加载、保存失败可继续、取消无副作用；完成页上的每个可见入口都能到达可用状态。

### 手机交互与显示

- 在实际手机尺寸及当前桌面预览容器检查首页、任务选择、场景、帮助、完成和笔记。
- 主操作始终露出，内容较多时滚动内容；返回与关闭可操作，触控目标至少 44px。
- 场景中间人物、订单物品和词语不被新增模块挡住；长文本、连续对话、较矮视口仍有可用操作空间。
- 推荐原因和完成事实用普通用户语言，不暴露数据字段、模型名或内部证据判定术语。

### 对话自由，任务隐藏，场景事实固定

- 人物先回应用户想说的内容，教学目标不能当作拒绝服务的理由。普通偏好、过去经历与本次点单分开，明确点单才改变实际订单。
- C02/C04 参考订单不再限制用户选择。堂食、带走及杯型按真实表达保存并交付，不逼用户复述指定答案。C03 用户也可以接受端来的杯子，此时不伪造修正错单的能力证据。
- 可以聊卡布奇诺，但现有场景仅提供拿铁与美式，不能许诺供货或展示不存在的菜单。
- 二选一后的 Yes 不擅自选答案，改为单项确认；对实际问出的那个选项的确认才推进。No 不自动认定另一个选项。先说出的小杯等信息保留。
- 聊天期间不弹任务催促。咖啡点单完成后仍可继续聊，用户点“结束对话”再看回顾。
- 对话页保留人物、场景、实际订单和帮助入口，隐藏任务编号、节点计数和判错颜色。主页经历选择仍保留。

### 验证边界

- 单元与浏览器测试验证状态分支和可见操作，不等于真人手机语音准确率验证。
- 本地实现完成不等于 Render 已上线；上线版本和本地版本分别记录。
- 首版目标是证明完整闭环可用。用户是否更愿意回来、延迟表达是否改善，需要后续真实使用观察，不在界面宣称已经证明。
