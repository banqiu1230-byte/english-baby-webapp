# 对话逻辑与场景扩展

## 产品约束

对话自由，任务用于后台识别经历和学习证据。用户可以聊天、求助、拒绝、提前回答、改变主意；教学目标不能覆盖用户真实选择。图片、人物和可用物品是固定事实，模型不能凭空补充。

## 共用流程

`识别后的原话 + 实际问题 + 当前场景事实 → SceneDialogue.evaluate → 场景规则校验 → 程序提交事实 → 播音与下一幕`

- 正常回答、步骤衔接时的回答、服务端本地识别使用同一个 `evaluate`。
- 结果统一为 `decision / conversation / help / clarify / unresolved`。只有确定的 `decision` 可以改变事实。
- 过期、重复的结果归为 `ignored`，不会播音、重新提问或写入学习记录。
- 已能在本地确定的输入不额外等待语义服务。未解决的候选由原有 DeepSeek 服务理解，实时人物负责回答用户。
- `semanticSpec` 从场景配置生成目标、可选值、当前事实和限制。服务端不再维护一份咖啡/早餐选项清单。
- 模型只返回候选意思；`validateCandidate` 重新经过场景规则，不接受模型提供的 `world`、`complete` 等结果。浏览器收到候选后再按当前世界版本校验。
- `isCurrentTurn` 统一检查练习、场景、步骤、消息修订及阶段，防止旧回复改动新状态。

## 场景负责什么

`scene-dialogue.js` 的场景适配器声明：

| 配置 | 用途 |
| --- | --- |
| `tasks` | 场景任务、实际问题、可选值及显示文案 |
| `worldKey` | 当前事实在应用状态中的位置 |
| `fields` | 事实变化对应的学习项 |
| `facts / constraints` | 已确认事实、物品范围、不可虚构的内容 |
| `evaluate(input)` | 预览当轮意思，返回统一结果，不修改页面或原世界 |
| `validateCandidate(input, candidate)` | 按相同事实规则验证模型候选 |

咖啡继续由 `coffee.js` 管理订单、错单、留杯和完成条件；早餐由 `breakfast.js` 管理选饮料、递杯、添加饮料的前置条件。不同动作不强行共用一个状态机。机场、办公室的任务声明已集中在适配器中，页面直接读取，避免问题文案出现两份。

`app.js` 和 `breakfast-ui.js` 仍负责把已验证的结果提交到对应场景、刷新图片、记录学习证据、播放声音。音频生命周期由原有 voice runtime 管理。

## 对话界面和运行规则共用

咖啡、早餐、机场、初次拜访、面试共用同一个对话界面和运行流程。新增场景只配置角色、图片、话题、帮助内容与可操作的场景事实，不复制一套对话气泡、语音控制、故障恢复或自动推进规则。

- **发言先被接住。** 任务条件成立时立即记录证据，但不取消正在生成或播放的角色回复，也不因为回复带有问号就替换成固定确认语。
- **真实追问交还话轮。** 每个场景都等待用户回应当前追问；没有答复时不靠超时跳到下一题。用户明确要求继续时，使用同一个推进调度器。
- **帮助意图只有一处定义。** 重听、慢一点、释义、提示、示范和暂停由 `DialogueRules.supportIntent` 识别，面试复用相同结果。询问具体词语时保留上下文对话；明确请求当前题目解释或点击帮助时才使用该题的辅助内容。
- **文字和声音对应同一问题。** 实际角色回复即使只有字幕，也要更新相同的对话上下文；技术状态和用户请求的提示不能伪装成新问题。
- **故障不属于角色台词。** 已确认的用户原话保留在对话里，连接或播放错误仅作为技术状态展示，不插入“没听清”的虚构回复，不把它写成下一轮需要回答的问题。
- **进度只读已确认目标。** 顶部进度、存档和完成判定使用实际已覆盖的任务；跳题不加进度，单题复习只显示该题的 0/1 或 1/1，恢复练习读取原有证据。
- **组件和布局共用。** 顶栏、任务进度、字幕、气泡、操作栏、全部对话使用共享样式；咖啡订单、早餐物品等内容组件可按实际需要显示。字幕开关不移除“全部对话”入口，转写状态变更不得推挤气泡。
- **传输队列保持顺序。** 暂时拥堵时保留音频并等待发送，不能把正常的集中发送当作断线；服务器和浏览器使用一致的 60 秒缓存上限，持续异常仍走明确故障恢复。

服务端通过 `conversationFlowInstructions` 复用相同的对话与推进约束；角色背景、语言难度和场景事实另行提供。前端通过共用的话轮、字幕上下文与推进调度器执行这些约束。

## 说不出来时的共同辅助

任务通过 `support.responseMode` 声明辅助方式，不能根据场景名称复制帮助界面。简单选择保留词汇提示；需要组织经历或观点的任务设置 `structured`，点一次提示便在顶部任务卡内展示英文填空开头和中文题意；回答思路与完整示例可展开。查看开口提示记作帮助，展开示例才记作完整示范；这些内容都不参与任务完成判定。

顶部任务卡和底部提示按钮控制同一个内联提示区，不再打开帮助浮层或复制到底部悬浮卡。当前话题标签与提示标题共用当前任务；提示保持对话、历史与麦克风可操作，不自动打开麦克风，也不替用户发言。学习者可以只说一点、中文想法或英文片段；角色根据真实意思帮助表达，不补造经历或业绩。换题、出现新的真实问题和退出时清除旧提示，重新展开时读取当前问题。

如果角色提出了任务之外的真实追问，共用 `/api/conversation-help` 根据实际问题和最近对话生成辅助，不套用原任务模板。请求绑定当前练习、任务和问题，关闭或换题后丢弃迟到结果。失败时保留实际问题与通用思考用语，明确展示重试入口，不伪造题意或角色台词。阅读帮助时暂停催促和自动推进。首次识别到有效语音通过 `confirmLearnerTurn → learnerTurnStarted` 解除阅读暂停，提示保留供照读，由同一个话轮调度器接续；噪声和过期识别不会释放暂停。关闭提示同样恢复调度，重复关闭或重复识别不重复恢复。

回归需同时验证共享规则与各场景事实：真实追问、短回答、求助、语音缺失但文字已返回、连接失败、迟到回复、重置和续练、复习、跳题、自然收尾。不得通过恢复旧的强制跳题、删除用户话语或改写合法角色回复来让测试通过。

## 对话和提示共用查词

`word-lookup.js` 为实时字幕、全部对话和顶部提示里的英文提供同一个查词入口。文字与换行保持原样，点击后显示句中词义；固定短语可一起解释和高亮。`/api/word-meaning` 只解释实际句子，服务端校验返回词组包含所选词且来自原文。缓存按句子和所选位置区分，避免同一个词在不同语境下混用意思。请求超时可重试，关闭、换题或原文变化后丢弃迟到结果。

逐字字幕使用已经收到的完整句子查词，尚未显示完整的单词不提供点击。同一条字幕继续显示或结束播放时保留词卡和高亮；真正改句、切题或退出才清理。词卡不会因字幕容器的程序滚动而消失。

查看词义暂停催促和自动推进，用户真实开口或关闭词卡后恢复；查词只记作释义帮助，不改变任务完成或经验值。`word-pronunciation.js` 在明确点击后调用本地英文语音，避开人物回复和用户发言，不调用人物对话服务。播放期间及短暂尾音从麦克风上传中排除，结束、失败、超时或取消都会恢复采集，不改变用户的麦克风开关。`npm run test:word-lookup-browser` 验证移动端点击、短语、长句、提示示例、错误恢复以及话轮状态。

## 新增场景的步骤

1. 声明实际存在的人物、物品、可改变的事实和完成条件。
2. 编写一个小的场景规则模块，预览/应用合法状态变化；保持输入不变，必要时带版本号和事件去重。
3. 在共享入口注册适配器。无需再分别为“正常回答、过渡期回答、后台识别”添加场景判断。
4. 接入场景图片、UI 展示、NPC 背景及实际提交逻辑；这部分仍属于新场景制作，不是单靠配置就会自动生成。
5. 按同一套行为回归：选择、改口、提前回答、实际问题下的 yes/no、聊天提到物品、求助、不可用物品、重复/迟到反馈、任务完成后继续聊天。

`scene-dialogue.test.js` 中的酒店适配器是隔离的扩展验证，不是已上线的酒店场景。

## 本次边界

这是一轮共享入口和校验协议的重构，保留现有场景行为、响应节奏与小任务粒度存档。没有新增英语水平分级，也没有重写整个语音系统。

现有场景的短句解析仍然保留；复杂表达依赖语义理解。本次没有将语义返回值升级为任意多字段计划，咖啡的多字段选择目前仍由其本地规则处理。后续应围绕“意图是否识别正确、事实是否能合法改变”扩展规则，不再在页面事件中添加某一句话的特判。
