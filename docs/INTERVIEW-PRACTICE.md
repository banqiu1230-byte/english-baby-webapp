# UI/UX 设计师英文面试练习

这组任务练习的是：听懂面试问题，用自己的真实经历回答，必要时澄清、补充和反问。Alex 是模拟面试官，不代表某家实际公司。内容不预设候选人的公司、年限、职位、项目成果或英语等级。

## 可以练什么

| 任务 | 对话内容 | 建议用时 |
| --- | --- | --- |
| I01 开场与自我介绍 | 寒暄 → 背景 → 个人职责 → 优势 → 选择项目 | 6–8 分钟 |
| I02 把作品集项目讲清楚 | 用户问题 → 个人贡献与限制 → 信息依据 → 关键决定 → 结果证据 → 复盘 | 10–15 分钟 |
| I03 设计判断与取舍 | 问题定义 → 有限时间验证 → 业务与用户取舍 → 视觉层级与一致性 → 不同用户和使用条件 | 8–12 分钟 |
| I04 协作、反馈与分歧 | 合作方式 → 设计分歧 → 模糊反馈 → 赶进度时确定范围 → 改变自己的判断 | 8–12 分钟 |
| I05 AI 工作流与质量把关 | 实际应用或尝试计划 → 工作过程 → 质量验证 → 信息边界 → 设计师的判断与责任 | 8–12 分钟 |
| I06 求职动机、反问与收尾 | 下一份工作的期待 → 能带来的贡献 → 成长方向 → 反问 → 自然结束 | 6–10 分钟 |
| I07 完整模拟面试 | 复用 16 个环节，串起开场、项目深聊、取舍、协作、AI、动机、反问和收尾 | 25–35 分钟 |

用时是练习安排参考，没有答题倒计时。六个专项共 31 个不同对话环节；完整模拟复用已有环节和学习目标，避免把同一个能力重复计成新内容。

对话顶部复用咖啡场景的任务进度卡片：显示本轮名称和话题短标签，当前话题为紫色、已完成为绿色、待聊为虚线。话题多时单行横滑，切换后自动露出当前话题，卡片高度保持一致。完成状态只读取 `coveredGoals`，跳过不计完成；续练保留原进度，单题复习只显示该题。

## 第一次怎么练

1. 先做 I01，用短句完成开场。不用一开始就说完整的长篇自我介绍。
2. 选一个最熟悉的真实项目练 I02。准备几条中文要点即可：问题、自己的工作、一个关键选择、实际观察到的结果。
3. 选择最不熟悉的一两个专项。一次只练一个环节也可以；没听懂时先澄清，想不起来时请求提示。
4. 最后用同一个项目做 I07，练习连贯地把话题接起来。如果公司或岗位要求已知，可以自己在对话中补充这些真实背景。
5. 再次练习时试着减少提示，换一种说法表达同一个意思。完成练习本身不等于已经达到某个英语等级或面试标准。

## 卡住时可以直接说

| 需要什么 | 可以说 |
| --- | --- |
| 没听清 | “Could you repeat the question?” |
| 想听慢一点 | “Could you speak more slowly?” |
| 不理解含义 | “What do you mean by constraints?” |
| 需要提示 | “Could you give me a hint?” |
| 想看一个句式例子 | “Could you give me an example?” |
| 需要想一想 | “Let me think.” |
| 想略过这题 | “Could we skip this question?” |
| 想结束当前练习 | “Could we stop here?” |

请求帮助、跳过和停止都不是答错。使用了提示，需要如实保留帮助记录；跳过某题不能记成已经展示了该能力。正式收尾时说 “That's all” 应按自然结束理解，不能和中途停止混为一谈。

## 回答时怎样避免背稿

寒暄和收尾提供简短帮助；其余 29 个实质性问题提供中文释义、2–3 条具体回答思路，以及一句英文填空开头。共用内联提示在点击顶部灯泡或底部提示后，直接在话题进度下展示英文开头与题意，回答思路和完整示范可按需展开。麦克风和对话始终可操作，可边看边说；不再使用提示浮层或“带着这句说”的第二步。

例如个人职责题可以先想“亲自负责什么 → 做了什么或交付了什么 → 与团队其他人的分工”，再从 `I was responsible for [你负责的具体工作].` 开始。思路是可选组织方式，不是必须说齐的清单；一句真实、能理解的回答也可以。

开头中的中文方括号说明需要填什么；完整示范里的 `[project]`、`[actual scope]` 等也是占位内容，要换成自己的真实信息。示范不代表候选人已经做过这些事。没做过、尚未测量或仍不确定，也可以照实说；假设做法要明确用假设方式表达。

项目题可以沿着“情境 → 自己做了什么 → 为什么 → 结果或未知之处”展开，但不强制一次说齐。面试官可以自然追问一个相关细节；不要求复读关键词、方法名称或某个标准答案。

没有可靠数据，可以说：

> We have not measured the impact yet. What I can say is [observable outcome].

这里的 `[observable outcome]` 必须是你确实观察到的事情。尚未上线、只做过原型验证、有定性反馈但没有量化数据，都是可以诚实表达的状态。不要把团队成果全说成自己完成，也不要把工具生成的内容当成独立证据。

没有相应经历时，可以说明自己会如何处理一个假设情境。Alex 应明确区分假设讨论与真实经历，不能替候选人补出一个“成功故事”。反问环节里，候选人提出的问题就是有效回应；暂时没有问题也可以直接说明。

## 内容与集成约定

- 内容文件：`interview.js`，浏览器导出 `globalThis.Interview`，Node 导出 CommonJS。
- `missions`：`id`、`title`、`goal`、`description`、`duration`、`taskIds`。
- `tasks`：31 个唯一的 `interview-` 前缀 ID；含 `prompt`、`label`、用于进度卡片的 `progressLabel`、`hint`、`support`、`rubric`、`keywords` 和可选 `followup`。
- `support`：保留 `meaning` 中文释义、`starter` 简短口头提示、`model` 可选完整语言示范。新增 `responseMode: 'structured' | 'concise'`、`answerPlan: string[]`、`answerStarter: string`，供同一个帮助面板按回答难度展示。`structured` 有 2–3 条中文思路与一句英文填空开头；寒暄与收尾为 `concise`，不显示回答提纲。
- `supportFor(taskOrId)`：按任务对象或完整 ID 返回同一份 `task.support`；未知任务返回 `null`。I07 复用相同内容，不生成第二套帮助。
- `learningDetails[taskId]`：`[targetId, label, meaning, model, hint]`，供渐进帮助和学习记录接入。
- `tasksFor(missionId)` 按任务顺序返回步骤；`getMission` 对无效 ID 回退 I01；`taskById` 对未知任务返回 `null`。
- `instructionsFor(taskId)` 提供面试官行为与当前话题规则。先承接候选人真实回答，再决定是否自然追问；最多一个可选追问，不反复要求同一答案。
- `classifyTurn(text)` 仅做明确对话控制意图的路由：`empty / repeat / slower / clarify / help / pause / skip / stop / answer`。`answer` 表示交给语义理解，不代表内容正确或完成。
- `keywords` 用来提供语言帮助，禁止用作通关门槛。候选人的澄清问题、反问、诚实的不确定和简短回应必须结合上下文判断。
- `rubric` 是对话理解建议，不是要求候选人全部满足的打分清单。
- 学习记录区分开口回答、使用帮助、明确跳过和技术问题；不根据关键词数量推断英语熟练度、岗位匹配度或招聘结论。

新增专项时先新增内容与有效任务 ID，再接入入口、语义理解、帮助和真实返回路径。不要只加一张“可点击”的场景卡而没有可完成的对话。

## 内容验证

`node --test interview.test.js` 覆盖任务引用与完整模拟复用、29 个实质性问题的具体回答思路与填空开头、简短寒暄的帮助模式、无经验和无数据的诚实表达、模板不杜撰用户履历、请求帮助与真实回答区分、反问与收尾语义，以及浏览器 / CommonJS 导出一致性。

这些测试验证内容结构和路由边界；真实语音识别、模型回复质量、页面入口和退出回顾需要在集成后单独验证。
